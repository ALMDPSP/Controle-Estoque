CONTROLE DE ESTOQUE — ENTRADA E SAÍDA DE EQUIPAMENTO
======================================================

O que é:
Um programa em Python (Flask) com página web, para cadastrar itens:

  - Código do item        - NF de entrada
  - Descrição              - Data de entrada
  - Qtde                   - NF de saída
  - Localização             - Data de saída
  - VD da loja que vai receber o item

Agora o programa tem:
  - LOGIN por usuário e senha (cada pessoa com o seu)
  - Banco de dados de verdade (não é mais um arquivo Excel solto —
    isso é o que permite hospedar na internet sem perder dados)
  - Botão "Exportar para Excel" a qualquer momento, que baixa um
    .xlsx com tudo o que está cadastrado
  - Pronto para subir no GitHub e publicar no Render


PARTE 1 — RODAR NO SEU COMPUTADOR (opcional, para testar antes)
------------------------------------------------------------------
1. Instale o Python 3: https://www.python.org/downloads/
2. No terminal, dentro da pasta do projeto:

       pip install -r requirements.txt
       python app.py

3. Abra http://localhost:5000
   Usuário: admin   Senha: admin123
   (Depois de entrar, vá em "Gerenciar usuários" e crie os usuários
   reais da equipe — e pode criar um admin novo e excluir o "admin"
   padrão, se quiser.)

Localmente ele usa um arquivo estoque.db (SQLite) — não precisa
configurar banco nenhum para testar.


PARTE 2 — COLOCAR NO GITHUB
------------------------------------------------------------------
1. Crie uma conta em https://github.com (se ainda não tiver).
2. Crie um repositório novo (botão "New repository"), pode deixar
   privado. Não escolha "Add a README" nem ".gitignore" (nós já
   temos um).
3. No terminal, dentro da pasta do projeto:

       git init
       git add .
       git commit -m "Primeira versão do controle de estoque"
       git branch -M main
       git remote add origin https://github.com/SEU-USUARIO/SEU-REPOSITORIO.git
       git push -u origin main

   (troque "SEU-USUARIO/SEU-REPOSITORIO" pelo endereço que o GitHub
   te mostrou ao criar o repositório)


PARTE 3 — PUBLICAR NO RENDER
------------------------------------------------------------------
Aviso importante sobre o plano GRATUITO do Render (para você decidir
com consciência):
  - O banco de dados PostgreSQL gratuito EXPIRA 30 dias depois de
    criado (com mais 14 dias de tolerância antes de apagar os dados
    de vez). Ou seja: ótimo pra testar, ruim pra usar de verdade.
  - O serviço web gratuito "dorme" depois de 15 minutos sem acesso,
    e demora uns 30-60 segundos pra acordar na próxima vez que
    alguém abrir o link.
  - Para uso real e contínuo pela equipe, o recomendado é o banco
    pago (a partir de ~$6-7/mês) e o serviço web pago Starter
    (a partir de ~$7/mês). Dá pra começar no gratuito só para testar
    o sistema com a equipe antes de decidir.

Passo a passo (pelo painel do Render, mais confiável que o arquivo
render.yaml, cujos nomes de campo mudam com o tempo):

1. Crie uma conta em https://render.com (dá pra entrar direto com o
   GitHub).

2. Criar o banco de dados:
   - No painel, clique em "New +" → "PostgreSQL"
   - Dê um nome (ex: estoque-db) e escolha o plano (Free para testar,
     ou um pago para uso real)
   - Depois de criado, copie o valor de "Internal Database URL"
     (vai usar no próximo passo)

3. Criar o serviço web:
   - "New +" → "Web Service"
   - Conecte sua conta do GitHub e escolha o repositório que você
     acabou de criar
   - Runtime: Python
   - Build Command:  pip install -r requirements.txt
   - Start Command:  gunicorn app:app
   - Em "Environment Variables", adicione:
       DATABASE_URL   = (cole o "Internal Database URL" do passo 2)
       SECRET_KEY     = (qualquer texto longo e aleatório, ex: uma senha forte)
       ADMIN_USER     = admin  (ou o nome que quiser)
       ADMIN_PASS     = (uma senha forte, para o primeiro acesso)
   - Clique em "Create Web Service"

4. Espere o deploy terminar (a barra de logs mostra o progresso).
   Quando terminar, o Render te dá um endereço tipo:

       https://controle-estoque.onrender.com

   Esse é o link que todo mundo da equipe vai usar — de qualquer
   lugar, não só da mesma rede.

5. Entre com o ADMIN_USER/ADMIN_PASS que você definiu, vá em
   "Gerenciar usuários" e cadastre um login para cada pessoa da
   equipe.

Atualizações futuras: sempre que você quiser mudar algo no programa,
edite os arquivos, rode "git add . && git commit -m "..." && git push"
e o Render publica a nova versão sozinho.


COMO O ACESSO É CONTROLADO
------------------------------------------------------------------
Cada pessoa tem usuário e senha próprios (criados na tela "Gerenciar
usuários", que só administradores veem). Sem login, ninguém consegue
ver ou mexer nos dados — o sistema redireciona para a tela de entrada.


ESTRUTURA DOS ARQUIVOS
------------------------------------------------------------------
app.py                -> o programa principal (rotas, login, API)
db.py                  -> acesso ao banco de dados (SQLite local / Postgres no Render)
templates/login.html   -> tela de login
templates/index.html   -> tela principal (cadastro e lista de itens)
templates/usuarios.html-> gestão de usuários (só admin)
requirements.txt       -> bibliotecas necessárias
Procfile               -> comando que o Render usa para iniciar o programa
render.yaml             -> modelo de configuração para deploy automático (opcional)
.gitignore              -> arquivos que não devem ir para o GitHub
